Building and Test-Running Gitea from Source on Ubuntu 22.04 (amd64)

This guide shows how to fetch the latest Gitea source from https://github.com/go-gitea/gitea.git, install the required toolchain, build the gitea binary, and run it for a quick test.

Required Go and Node.js versions change over time. This guide reads the Go version from the repository's go.mod and the Node.js requirement from package.json, so it stays correct for the latest source. Also see the official guide: Installation from source.

1. Install base packages

sudo apt update
sudo apt install -y git make curl ca-certificates build-essential jq

build-essential (gcc) is needed because the SQLite build tags use CGO.

2. Download the latest source code

git clone https://github.com/go-gitea/gitea.git
cd gitea

This checks out the main branch (the latest development code). To build the latest stable release instead:

git fetch --tags
git checkout "$(git tag -l 'v*' | grep -v -- '-' | sort -V | tail -n 1)"

3. Check the required tool versions

grep -E '^(go|toolchain) ' go.mod
grep -A3 '"engines"' package.json
grep -E '^(MIN_GO_VERSION|MIN_NODE_VERSION)' Makefile

Note the minimum Go and Node.js versions printed. Ubuntu 22.04's packaged Go and Node.js are too old, so install them from upstream.

4. Install Go

Pick the version from go.mod (or the latest from go.dev/dl):

GO_VERSION="$(curl -fsSL 'https://go.dev/VERSION?m=text' | head -n 1)"   # e.g. go1.xx.x
curl -fsSLO "https://go.dev/dl/${GO_VERSION}.linux-amd64.tar.gz"
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf "${GO_VERSION}.linux-amd64.tar.gz"

echo 'export PATH=$PATH:/usr/local/go/bin:$HOME/go/bin' >> ~/.bashrc
source ~/.bashrc
go version

5. Install Node.js and npm

Use the current LTS release (Node.js 22 or newer; adjust the major version if the requirement above is higher):

curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt install -y nodejs
node --version
npm --version

6. Build Gitea

From inside the gitea directory:

TAGS="bindata sqlite sqlite_unlock_notify" make build
  • bindata embeds all web assets into one binary (required for production use).
  • sqlite sqlite_unlock_notify enables SQLite support, which is convenient for testing.
  • make build runs make frontend (Node.js) and make backend (Go).

The first build downloads many dependencies and can take several minutes. When it finishes, a gitea binary is created in the current directory:

./gitea --version

7. (Optional) Run the unit tests

TAGS="sqlite sqlite_unlock_notify" make test-backend

The full test suite is long-running; to run a single package, for example:

go test -tags "sqlite sqlite_unlock_notify" ./modules/util/...

8. Test run

Gitea refuses to run as root, so use a normal user. For a quick test, run it directly from the build directory:

./gitea web

Open http://localhost:3000 (use the server's IP address for remote access; make sure port 3000 is reachable, e.g. sudo ufw allow 3000/tcp). The install page appears on first launch:

  1. Choose SQLite3 as the database type.
  2. Keep the default settings (or adjust the Server Domain and Base URL).
  3. Optionally create an administrator account, then click Install Gitea.

Verify from the command line:

curl -I http://localhost:3000/
curl -s http://localhost:3000/api/healthz

Stop the server with Ctrl + C. Data created during the test is stored under data/, custom/, and log/ in the working directory and can be deleted to start over.

9. Updating later

cd gitea
git pull
TAGS="bindata sqlite sqlite_unlock_notify" make build

Troubleshooting

  • Go version errors: confirm which go points to /usr/local/go/bin/go, not /usr/bin/go.
  • Node.js version errors: confirm node --version meets the minimum from step 3.
  • gcc: not found: install build-essential.
  • Out-of-memory during the frontend build: use a machine with at least 4 GB RAM or add swap.
  • "Gitea is not supposed to be run as root": run as a non-root user.
